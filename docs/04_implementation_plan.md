# Implementation plan

*Companion to [03_project_proposal.md](03_project_proposal.md). Draft, 6 Nov 2026.*

Goal: a verified, submission-ready improvement on all three tasks by the **20 November 2026
milestone (23:59 UTC)**, produced by one public Kaggle notebook.

## 1. Principles

- **Verify everything before it counts.** Each new circuit goes through: an exact classical
  model, a quick partial check, then the full official verifier.
- **One task at a time, always submittable.** Any task we haven't improved yet uses its
  baseline circuit (ratio 1.0), so a valid submission exists at every stage.
- **Build from source.** Every circuit is generated by code in this repo, not stored as a
  file. This keeps the notebook reproducible and avoids uploading the 800 MB dqi file.
- **Measure costs, don't assume them.** Use kickmix's own operation counts.

## 2. Tooling (done)

- kickmix 1.0.0 from PyPI; checked to give identical results to the Kaggle build.
- Official verifiers, run locally. Baselines reproduced exactly.
- `tools/quick_invsqrt.py`, `tools/quick_dqi.py`: fast partial checks.
- `tools/profile_marks.py`: Toffolis per named stage.

Measured primitive costs (kickmix 1.0.0), which the designs below rely on:

| Primitive | Toffolis | Notes |
|---|---|---|
| n-bit add of a quantum register | about n − 1 | 20-bit: 19 |
| Same, controlled by a qubit | about 2n + 3 | 20-bit: 43 |
| Table lookup, S entries | about S − 2 | 256 entries: 254 |
| Clearing that lookup | far less | 64 → 10, 128 → 18, 256 → 25 |
| AND into a fresh qubit | 1 | Clearing it by measurement costs 0 |

## 3. Workstreams

### 3.1 invsqrt (highest priority)

**Algorithm.**

1. Normalize: count leading zero pairs s and shift x so that M = x·4ˢ/2²⁰ lies in [1, 4)
   (reuse the baseline's 120-Toffoli method).
2. Turn s into binary with CNOTs only (the leading-zero flags form a "thermometer" code).
3. Look up the polynomial coefficients for M's segment from the top bits of the normalized x.
4. Evaluate the polynomial with Horner's rule, using truncated fixed-point multipliers.
5. Shift the result left by s with a 4-stage binary shifter (shifts of 1, 2, 4, 8).
6. Apply the phase with one gate per output bit (the ½- and ¼-turn bits are free; the ⅛-turn
   bit costs one T; the rest are rotations).
7. Undo steps 5 to 1. Clear the coefficient lookup with the cheap measurement-based method.

**Design search.** A numpy model reproduces the circuit's exact fixed-point arithmetic on all
3.1M inputs in seconds. We will search over:

- polynomial degree (2 or 3) and number of segments;
- bit widths of each coefficient and intermediate register;
- which partial-product bits each multiplier keeps;
- coefficients fitted against the truncated arithmetic (minimax over each segment, then
  local integer adjustments).

The objective is the estimated qubits × (Toffolis + T/4), subject to worst error at most
about 0.9 × tolerance. The remaining margin pays for the rotations.

**Checks.**

1. Model vs circuit: simulate the circuit on sampled inputs and require bit-for-bit
   agreement with the model's output register.
2. Quick verify on the first 65,536 inputs.
3. Full verify: all 3,133,452 inputs × 64 shots (about 19 minutes locally).

**Exit criterion:** passes the full verifier with Q × C at most 25% of the baseline's.

### 3.2 dqi

**Step 1: inversion in the tower field GF((2⁶)²).**

- Find a basis change between the competition's polynomial basis and a tower basis. This is
  a 12×12 binary matrix, applied in place with CNOTs (free).
- Inverse of a = a₀ + a₁y: norm N = a₀² + a₀a₁ + νa₁² (one GF(2⁶) multiply), then N⁻¹ in
  GF(2⁶), then a⁻¹ = (a₀ + a₁ + a₁y) · N⁻¹ (two GF(2⁶) multiplies).
- Clear intermediate products by measurement. Field products are bilinear, so the phase fix
  is a set of CZ gates (free).
- Use it in the Forney step (4,095 times), and also in the Euclid quotient divisions.
- Unit test: invert all 4,095 nonzero field elements against `km.GF2Field`.

**Step 2: a cheaper multiplier.** Implement a bilinear multiplication formula (one Toffoli
per product term, linear forms computed with CNOTs) with fewer than 63 terms. Unit test on
random pairs, then swap it into the Euclid sweep.

**Step 3 (stretch): leaner schedule.** Cut wasted multiply sweeps, or reduce workspace qubits.
Each change gets a design note before any code.

**Checks.** Unit tests per primitive; 512-shot quick checks; a full 102,400-shot verify
(about 25 minutes locally) for each candidate submission. Keep the failure count at 0 unless
an approximation is a deliberate choice.

**Exit criterion for the milestone:** full verify passes with cost at most about 80% of
the baseline's.

### 3.3 dfthcsos

**Needs the starter kit** (trainer and circuit builder).

1. Reproduce the starter kit's baseline run and match the score 3,355,599,588.
2. Precision study: retrain at brot = 11 and 10 with quantization in the loss; pick words
   directly instead of rounding.
3. Shape study: sweep R and B down from 65 and 60 while staying under 20 mHa.
4. Angle-circuit study: batch size J under the 128-qubit cap; sort rows so identical
   segments repeat; measure Toffolis with the simulator.
5. Pick the best verified combination.

Each evaluation is about 80 s locally, so the sweeps must be planned rather than exhaustive.

**Exit criterion:** passes the verifier with a lower score than 3.356×10⁹. If the starter kit
isn't usable in time, submit the baseline for this task.

## 4. The submission notebook (to be built after the circuits)

A single self-contained Kaggle notebook, so the milestone prize's public-notebook rule is met.

| Section | What it does |
|---|---|
| 1. Setup | Find the competition data under `/kaggle/input`; import kickmix (dataset copy or PyPI); set output paths |
| 2. Settings | Switches: which tasks use improved vs baseline circuits; verification level (none / quick / full) |
| 3. invsqrt | Build the improved circuit from source; quick check; optional full verify |
| 4. dqi | Build the improved decoder from source; quick check; optional full verify |
| 5. dfthcsos | Build the angle circuits and `submission.npz`; run the verifier (about 80 s) |
| 6. Package | Write `submission/` with `invsqrt.kmb`, `dqi.kmb`, `dfthcsos/…`; zip to `submission.zip`; check the zip layout |
| 7. Report | Table of qubits, Toffolis, cost, ratio vs baseline and estimated overall score |

Design rules:

- No network access needed. All code lives in the notebook (generated from this repo's
  sources).
- If any check fails, that task falls back to its baseline circuit and the notebook says so,
  so the zip is always valid.
- Expected run time on Kaggle (4 cores): build in a few minutes; quick checks in a few
  minutes; full verification of all three about 30–45 minutes (optional).
- The dqi file is about 800 MB uncompressed. The notebook builds it directly in
  `/kaggle/working`, so nothing large has to be uploaded.
